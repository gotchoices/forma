# Proton Lab — Spec

Interactive workbench for exploring the **clover-shaped proton sheet** — a
corrugated 2-torus whose cross-section has 3-fold symmetry (three "lobes"
of positive curvature and three "saddles" of negative curvature) and whose
ring sweep includes a chiral twist. This is the substrate proposed by
[projects/sheet-proton/work/clover-quarks.md](../projects/sheet-proton/work/clover-quarks.md)
as the geometric host of the proton, neutron, and their fractional-charge
quark constituents.

Single HTML file, no build step. Uses the standard `totu-viz.js` /
`totu-viz.css` infrastructure (Three.js 0.163.0).

Context: [sheet-proton](../projects/sheet-proton/) Phase A/B; the analytical
math is complete and we now want to *see* the surface and play with its
parameters.

---

## 1. Physics Model

### 1.1 The clover cross-section profile

A closed plane curve `P(φ) = (X(φ), Y(φ))` made from six circular arcs
under D₃ symmetry (3-fold rotation + mirror through each lobe axis):

- **Three lobe arcs** (positive curvature, radius `r_lobe`), each spanning
  240° on its parent circle. Lobe centers sit at the three cube roots of
  unity scaled by `d = r_lobe + r_saddle`: `d·(cos 2πk/3, sin 2πk/3)` for
  `k = 0, 1, 2`.
- **Three saddle arcs** (negative curvature, radius `r_saddle`), each
  spanning 120°. Saddle centers sit at the rotated positions
  `d·(cos(2πk/3 + π/3), sin(2πk/3 + π/3))`.

The 240°/120° split and the kissing-circles relation `d = r_lobe + r_saddle`
are forced by D₃ symmetry and tangency (no free choice). See
[clover-quarks.md §7](../projects/sheet-proton/work/clover-quarks.md).

Total arc length: `L_total = 2π · (2·r_lobe + r_saddle)`.
Profile parameter `φ ∈ [0, 2π)` is normalized to one full traversal at
constant arc-speed. Within one fundamental domain `φ ∈ [0, 2π/3)`:

- Lobe portion: `φ ∈ [0, φ_L)` where `φ_L = (2π/3) · 2·r_lobe / (2·r_lobe + r_saddle)`
- Saddle portion: `φ ∈ [φ_L, 2π/3)`

The profile is generated by sampling each arc analytically, mapping
arc-length monotonically into `φ`.

### 1.2 The corrugated torus

Sweep the profile around a major ring of radius `R_major` lying in the
horizontal plane. The **surface mesh** is built by sampling the
*un-rotated* clover `P(φ)` and then **physically rotating** that 2D
sample by an angle `α = τ·θ` in the cross-section plane before embedding
it:

```
samp        = P(φ)                                      (un-rotated)
(Pxr, Pyr)  = R_α · (samp.x, samp.y)        where α = τ·θ
r⃗(θ, φ)   = R_ring(θ) + Pxr · N̂(θ) + Pyr · B̂
R_ring(θ)   = R_major · (cos θ, sin θ, 0)
N̂(θ)       = (cos θ, sin θ, 0)         (outward radial)
B̂          = (0, 0, 1)                 (vertical)
```

That is — the *clover itself rotates* about the ring spine as θ advances.
This is a genuine 2D rotation applied to the cross-section coordinates,
not a parameter shift inside P. The visual effect is that the three
lobes form a 3D helix.

The two control parameters affect the visualizer differently:

- **`τ`** is the **physical twist rate** — the rotation `R_{τ·θ}` applied
  to every cross-section. The surface *itself deforms* when `τ` changes.
  Closure (the surface meeting itself after one ring rev) requires
  `R_{2π·τ}` to map the clover to itself. By the clover's 3-fold
  symmetry `P(φ + 2π/3) = R_{2π/3}·P(φ)`, this is satisfied iff `τ` is
  a multiple of `1/3`. So `τ ∈ {…, −1/3, 0, 1/3, 2/3, 1, …}` —
  selectable in **1/3 steps**.

- **`s`** is a **coordinate shear** — it does **not** appear in the
  surface mesh, but it *does* apply to both grid lines and path tubes
  so they share a single coordinate frame. A line or path uses the
  effective rotation rate `(τ − s)` instead of `τ`:

  ```
  α_overlay(θ) = (τ − s) · θ
  ```

  - `s = 0`: overlays align with the surface's natural twist (they
    follow the same helical lobes).
  - `s = τ`: overlays use zero rotation rate — grid lines become
    horizontal rings and paths trace fixed-cross-section circles. Both
    cut *across* the physical lobe pattern.
  - other `s ∈ multiples of 1/3`: overlays spiral at a different rate
    from the surface's lobes, exposing the misalignment between the
    coordinate frame and the embedding.

  Shear is **quantized to 1/3 steps** (selectable via a stepper, just
  like `τ`) so that overlay rotations under the corrugated torus's 3-fold
  closure are always clean.

  Path closure condition: `n_θ · (τ − s) ∈ ℤ`. With both `τ` and `s` in
  1/3 steps, this is satisfied for any `n_θ` that is a multiple of 3
  (and trivially for any integer `n_θ` when `(τ − s)` happens to be
  integer). The preset proton/neutron paths use `(n_θ, n_φ) = (3, 0)`
  so they close cleanly for every allowed `(τ, s)` pair.

### 1.3 The three independent geometric scalars

| Parameter | Symbol | Default | Range |
|---|---|---|---|
| Ring radius | `R_major` | 3.0 | 1.0 – 8.0 |
| Lobe radius | `r_lobe` | 0.80 | 0.05 – 2.0 |
| Saddle radius | `r_saddle` | 0.40 | 0.05 – 2.0 |
| Twist | `τ` | 1/3 | discrete steps of 1/3; deforms the surface |
| Shear | `s` | 0   | discrete steps of 1/3; tilts overlays only |
| Fractal level | `L` | 1 | 1, 2, or 3 — see §1.6 |
| `r_L2 / r_p` | — | 0.50 | (0.406, 0.577) when L ≥ 2 |
| `r_L3 / r_p` | — | 0.45 | (0.349, 0.518) when L ≥ 3 |

`d = r_lobe + r_saddle` is derived (not a slider). When the profile would
self-intersect (`d < 0`) or when `r_lobe + d > R_major` (the inner lobe
crosses the donut hole) we warn but still render.

### 1.6 Fractal cross-section (clover-on-clover)

Per [projects/sheet-proton/work/clover-on-clover.md](../projects/sheet-proton/work/clover-on-clover.md)
(rewritten §3), the cross-section can recurse beyond the base clover.

- **Level 1:** the base clover described in §1.1.
- **Level 2:** each level-1 lobe arc (each L120) is bisected and its central
  60° replaced by a smaller-scale primitive S30-L60-L60-S30.
- **Level 3:** each level-2 sub-lobe (each L60) is similarly bisected.

The level-(n+1) primitive's lobe radius `r_L_(n+1)` is the user-controlled
free parameter; the saddle radius `r_S_(n+1)` is determined by the closure
constraint

  r_p = 2·r_L_new·cos(A/4) + r_S_new·(2·cos(A/4) − 1)

where `r_p` is the parent's kissing-circle radius and `A` is the parent's
angular extent (120° at level 2, 60° at level 3). The valid range for
`r_L_new / r_p` is shown above and matches the slider bounds.

When `L ≥ 2`, the analytical `profileAt(...)` path is bypassed and the
cross-section is built as a list of arcs (`buildFractalArcs`), sampled by
arc length into the same `(xs, ys, ks)` arrays consumed by the surface
mesh and the 2D preview canvas.

Saddle arcs are never bisected. Only sub-lobes from the immediately
previous level are bisected at each new level — remnants from earlier
bisections retain their original parent radius and are skipped.

### 1.7 Construction toggle — modulated clover (default)

A top-bar **construction** selector switches between two geometries:

- **Modulated clover** *(default)* — the current best-candidate proton/
  neutron construction from
  [projects/sheet-proton/work/modulated-clover.md](../projects/sheet-proton/work/modulated-clover.md).
  The cross-section is a *smooth* harmonic tube-function with three major
  and three minor lobes,

  ```
  w(t;θ) = 1 + a₁(θ)·cos 3t + a₂·cos 6t + i·( b₁(θ)·sin 3t + b₂·sin 6t )
  ```

  swept around the ring with a **half-twist** α(θ) = θ/2 and a θ-dependent
  major↔minor **modulation** a₁(θ), b₁(θ), embedded as
  ζ(t,θ) = ρ·e^{i(θ/2+t)}·w(t;θ). The modulation uses odd half-integer
  harmonics cos/sin((2k+1)θ/2), all antiperiodic in θ, so the surface still
  closes — via the half-twist identification (t, θ+2π) ~ (t+π, θ). The
  coefficients shipped are the charge-correct set from `modulated_clover.py`
  step 7 (Q_proton = +1, Q_neutron = 0 exactly). The proton and neutron are
  the two **(1/2, 1) tracks** t(θ) = t₀ + θ/2, offset by one cross-section
  piece (t₀ = ∓π/6); each closes in **one** ring revolution.

- **Naive arc clover** — the original piecewise-arc construction (§1.1–1.2).
  Kept so its **closure problem** can be seen directly: a literal-arc baryon
  path traverses its arc inventory (proton = 2 lobes + 1 saddle) with a
  φ-advance per ring revolution of 2φ_L + φ_S, strictly inside (2π/3, 4π/3)
  — never a whole tube wrap, so the locus does not return to its start.

When the construction is **modulated**, the arc-only controls (r_lobe,
r_saddle, fractal, τ, shear) are hidden; only R_major and opacity apply.

### 1.8 Closure test

For the selected baryon, the right panel shows a **closure test**: the path
is drawn *honestly* (no artificially-closing preset) and the 3D distance
between its start and end is reported. When that end-gap is non-zero the two
endpoints are marked with a green (start) and red (end) sphere joined by a
dashed line — making the closure failure visible. In the **naive arc**
construction the proton/neutron paths show a large gap (the closure
problem); in the **modulated clover** the (1/2, 1) tracks close to within
numerical zero (the solution).

### 1.9 Sheet view — κ(t, θ) heatmap

A second small canvas under the cross-section profile shows the **unrolled
(θ, t) sheet** (or (θ, φ) in arc mode) as a diverging heatmap of the
cross-section's planar tube curvature κ: red = convex (lobe), blue =
concave (saddle), brightness = magnitude (normalised by the 95th
percentile to suppress junction spikes in arc mode). Light gridlines mark
the six cross-section piece boundaries (modulated) or three fundamental
domains (arc).

When a baryon is selected, its track is overlaid as a diagonal:

- **Modulated** — t(θ) = t₀ + θ/2, a straight slope-½ diagonal that
  wraps once in t (consistent with the half-twist identification
  (t, θ+2π) ~ (t+π, θ)).
- **Arc (naive)** — φ(θ) = φ_start + (2φ_L+φ_S)·θ/2π for the proton,
  φ_L + 2φ_S for the neutron. The diagonal visibly **does not return to
  its starting φ** at θ = 2π — that vertical mismatch is the closure
  problem viewed in parameter space.

Green dot = track start; red dot = track end. The same colour code used
by the 3D closure markers, so the two views tell the same story.

### 1.10 Charge-segment overlay

A "**show charge segments**" checkbox under the particle controls switches
every active baryon's track from its solid identity-colour to a *segmented*
rendering: red where the tube-direction curvature κ is positive (convex —
the u-like contribution to the experienced-curvature integral) and blue
where κ is negative (concave — the d-like contribution). This visualises
the **operative charge integrand** the modulated-clover construction
relies on (§4.3 of [modulated-clover.md](../projects/sheet-proton/work/modulated-clover.md)):
the per-track sum of signed κ along the path is the baryon charge (+1
proton, 0 neutron). Both 3D paths and the (θ, t) sheet diagonals respect
the toggle, so the same red/blue pattern appears in both views.

When the option is **off** (default), each particle is drawn in its
identity colour: red shades for protons (`#ff5252`, `#d32f2f`, `#ff8a80`)
and violet shades for neutrons (`#ab47bc`, `#8e24aa`, `#ce93d8`). Blue is
reserved for the electron and green for the neutrino in future viz work.

### 1.11 Master particle checkboxes

To the left of each particle's row sits a master checkbox that gates the
whole group. With the master unchecked, no track for that particle type
is drawn regardless of which per-phase checkboxes are ticked; with it
checked, the three per-phase checkboxes determine which Z₃-replicas
appear. This makes it one click to toggle all protons (or all neutrons)
on and off without disturbing the individual phase selection.

### 1.12 Settings persistence

The full UI state (construction mode, particle-master + per-phase
checkboxes, show-charge toggle, view toggles, all geometric sliders,
fractal level) is auto-saved to `localStorage` under
`protonLab.state` on every change and restored on page reload. The
camera position continues to persist under its existing key
(`protonLab.camera`); named profiles continue to live under
`protonLab.profiles`.

### 1.13 Surface STL export

An **Export → Surface → STL** button in the left panel saves the current
surface mesh as binary STL using `three/addons/exporters/STLExporter.js`.
Particle paths, closure markers, and overlays are not included — only the
torus surface, suitable for 3D-printing or import into a modelling tool.

### 1.4 Particle assignments

Per [clover-quarks.md §3 & §12](../projects/sheet-proton/work/clover-quarks.md):

- **Up quark (u)** — one lobe arc; carries Q = +2/3.
- **Down quark (d)** — one saddle arc; carries Q = −1/3.
- **Proton (uud)** — composite traversing 2 lobes + 1 saddle of the
  cross-section per ring revolution; closure in 2 ring revolutions
  under literal-arc parameterization.
- **Neutron (udd)** — 1 lobe + 2 saddles per revolution; closure in
  1 revolution.

These are visualized two ways simultaneously:

1. **Region coloring** — the lobe arcs are tinted one color, saddle arcs
   another. When a particle is selected, the specific arcs assigned to
   that particle's quarks are highlighted at higher intensity; non-member
   arcs are dimmed.
2. **Path overlay** — for composite particles (proton, neutron), one or
   more closed curves are drawn on the surface as glowing tubes. Each
   path is parameterized in `(θ, φ)` by:

   ```
   θ(t) = 2π · n_θ · t
   φ(t) = 2π · n_φ · t + φ_offset
   ```

   with `t ∈ [0, 1]`. The closure condition (line 92 of
   [clover-quarks.md](../projects/sheet-proton/work/clover-quarks.md))
   on the corrugated torus is satisfied when `n_θ` revolutions plus the
   twist drift give an integer φ-winding. Built-in presets pick `(n_θ,
   n_φ)` and `φ_offset` to match each particle's expected geometry.

### 1.5 Geodesics (Phase 2)

A future addition. True geodesics on the corrugated torus require
integrating the geodesic equation with the induced metric (§10 of
clover-quarks.md). For v1 we draw **homotopy-class paths** (uniform-`(θ, φ)`
straight lines in parameter space), which give the right topology and are
sufficient to visualize the particle structures. The infrastructure (path
geometry generator, color coding) is in place to swap in true geodesics
later.

### 2.3 Left panel — Profiles (save/load)

- **[Delete]** button: removes the currently-selected profile.

- "Thin saddle" (χ = 0.25)
- "Flat torus limit" (τ = 0)
- "Double-twist" (τ = 2/3)

### 2.4 Right panel — Cross-section preview (2D)

A canvas (≈ 240 × 240 px) drawing the 2D profile `P(φ)` with:

- The 6 circle centers marked as small dots.
- A radial axis from origin to the lobe-1 tip (the reference direction).
- If a particle is selected, the highlighted arcs glow brighter; non-member
  arcs faded.
- Origin and `d = r_lobe + r_saddle` annotated.

This is the same shape that gets swept into 3D — gives the user immediate

|---|---|---|

### 2.6 Right panel — Info readout

Live values:

- `d = r_lobe + r_saddle` (kissing-circles distance)
- `r_max = 2·r_lobe + r_saddle`, `r_min = r_lobe` (radial extremes)
- `χ = r_saddle / r_lobe` (corrugation ratio)
- `ε = (2·r_lobe + r_saddle) / R_major` (aspect ratio, analog of metric-charge's `L_u/L_w`)
- Total surface area (numerical)
- Closure check: ✓ or warning for self-intersection

## 3. Rendering Details

### 3.1 Surface mesh

Mesh resolution: `N_θ = 240` segments around the ring × `N_φ = 180`
segments around the cross-section (~ 43k triangles). Adjust if performance
is an issue.

Construction:

1. Pre-sample the profile `P(φ)` at `N_φ + 1` uniformly-spaced φ values into
   a typed `Float32Array`. Each sample is `(P_x, P_y)`.
2. For each `(i, j)` pair, compute `θ_i = 2π·i/N_θ`, `φ_j = 2π·j/N_φ`,
   then evaluate `P(φ_j + τ·θ_i + s)` by re-interpolating the cached
   profile sample (the offset wraps modulo 2π).
3. Compute 3D position via the embedding formula and write into a
   `BufferGeometry` position attribute.
4. Compute per-vertex color by classifying φ-arg into lobe/saddle and
   blending with the particle highlight, then write into a vertex-color
   attribute.

The mesh is rebuilt whenever `R_major`, `r_lobe`, `r_saddle`, `τ`, or `s`
changes. Slider drags are responsive (rebuild < 16 ms for 43k tris).

Coloring: use a base lobe color (warm) and saddle color (cool), darkened
when the arc is not part of the selected particle and brightened when it
is. The neutral (no particle selected) state shows lobes and saddles in
their natural colors at medium intensity.

### 3.2 Path overlay (composite particle paths)

For each path, sample `N_path = 600` points along the (θ, φ) parameter
line, compute their 3D positions via the same embedding formula, push to
a `CatmullRomCurve3`, and wrap with a `TubeGeometry` of small radius.

Render multiple paths per particle (e.g., 3 paths for proton's three
quark constituents) with distinguishable colors (red, green, blue — the
QCD "color" labels, although here they only serve as visual differentiation
between constituents).

### 3.3 Cross-section preview (2D canvas)

Standalone 2D rendering using `Canvas 2D` context. The profile is sampled
densely (≈ 360 segments) and drawn as a single closed path with per-arc
stroke colors. Centers and tangents are drawn as small overlays.

### 3.4 Color palette

- Lobes (selected/active): `#ff6b6b` (red)
- Saddles (selected/active): `#4fc3f7` (blue)
- Inactive lobes: faded red
- Inactive saddles: faded blue
- Path colors: `#ff5252`, `#69f0ae`, `#40c4ff` (QCD r/g/b)
- Ring spine: `#ffd54f`
- Grid lines: rgba(255,255,255,0.18)

### 3.5 Camera

Default position: `(2.5·R_major, 1.5·R_major, 3.0·R_major)` looking at the
origin. `OrbitControls` for mouse interaction.

## 4. Interactions

### 4.1 Parameter changes

Any geometric slider rebuilds the surface mesh (and the cross-section
preview). The path overlays re-evaluate against the new surface.

### 4.2 Particle change

Switching the particle dropdown:
1. Updates the per-vertex color attribute (re-classifies lobes vs saddles
   and highlights particle members).
2. Rebuilds path-overlay tubes.
3. Updates the cross-section preview's highlight ring.
4. Updates the info readout.

### 4.3 Save/load

- **Save**: prompts for name, writes JSON blob `{ R_major, r_lobe,
  r_saddle, tau_num, tau_den, shear, particle, surface, wire, color,
  grid, path, spine }` to localStorage.
- **Load**: dropdown of saved profiles. Selecting one restores all values
  and rebuilds everything.
- **Delete**: removes the selected profile.

### 4.4 Keyboard shortcuts

- `r` — reset camera
- `g` — toggle grid lines
- `p` — cycle particle (none → u → d → proton → neutron → none)
- `+ / -` — increment/decrement τ by 1/3
- `s` — open save prompt (focus the save button)

## 5. Implementation Notes

### 5.1 File layout

```
viz/
  proton-lab.md          ← this spec
  proton-lab.html        ← the application
```

After creation: add a card to `index.html` and a row to `README.md`.

### 5.2 Math gotchas

- The 3-fold profile symmetry `P(φ + 2π/3) = R_{2π/3} P(φ)` means that
  changing `τ` by 1/3 leaves the surface mesh visually identical *up to
  a rotation of how individual lobes are labeled along θ*. Two
  observations follow:
  1. The user can verify the closure by visually walking around the ring
     and noting the constant lobe labeling for `τ ∈ multiples of 1/3`.
  2. If `τ` is set to a value *not* a multiple of 1/3 (which the UI
     forbids in v1), the surface would not actually close and the mesh
     would render with a visible seam — useful future feature.

- The "shear `s`" parameter is a continuous angle added to the profile
  argument *globally* (not per-θ). It does not break closure. It is
  useful for aligning the profile's lobe-1 with a chosen 3D direction
  before saving a snapshot.

- For very thin saddles (small `r_saddle / r_lobe`) the saddle arcs
  become tight indentations between large lobes. For very thick saddles,
  the profile becomes hexagonal-with-rounded-corners. Both regimes are
  geometrically valid and the visualizer handles both.

- The closure condition for paths (line 92 of clover-quarks.md) implies
  that a path with `(n_θ, n_φ) = (1, 0)` traces a helical curve on the
  surface that drifts in φ by `2π·τ` per ring revolution. With τ = 1/3,
  this is the `2π/3` drift that creates the third-integer momentum
  quantization.

### 5.3 Performance

The mesh has ~43k triangles. Re-meshing on slider drag should be < 16 ms
in any modern browser. If the user picks very high `N_θ × N_φ`, the mesh
can grow but the architecture supports it.

### 5.4 Validation on launch

At startup, the script computes `d = r_lobe + r_saddle` and `r_max,
r_min` from defaults and prints them to the bottom-left info overlay so
the user can verify the kissing relation holds.

## 6. Future Extensions (out of scope for v1)

- **True geodesics**: numerically integrate the geodesic equation
  with the induced metric from §10 of clover-quarks.md.
- **Mode density overlay**: solve the Laplacian eigenvalue problem
  (Phase C of clover-quarks.md) and color the surface by `|ψ|²` for a
  selected mode `(p, q)`.
- **Φ-quantization labels**: display `k_θ = q − p/3` values overlayed
  on the path-overlay tubes.
